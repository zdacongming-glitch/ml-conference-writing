# 论证与语言修改手册

以下是依据经典论文及官方审稿标准形成的**编辑建议**，不是会议硬性结构。按用户的修改范围和稿件实际贡献使用。

## 目录

- 贡献类型与主线
- 标题和摘要
- 引言与相关工作
- 方法与理论
- 实验、讨论与篇幅
- 句子与措辞
- 审稿回复及投稿前核查

## 贡献类型与主线

先用作者提供的证据回答：“读完此文，读者多知道什么，或者能够多做什么？”

| 实际贡献 | 适宜的论证主线 | 首先检查的缺口 |
| --- | --- | --- |
| 新方法或架构 | 具体障碍 → 核心思想 → 可执行构造 → 检验 | 改善是否来自所称的新思想 |
| 理论结果 | 问题与已知边界 → 新结果 → 条件与困难 → 证明思想 | 新结论相对最接近结果改变了什么 |
| 经验规律或机制研究 | 可检验问题 → 对照 → 稳定观察 → 解释及反例 | 观察能排除哪些解释，仍有哪些混杂 |
| 负结果 | 明确待检验的主张 → 有力测试 → 失败范围 → 对研究的影响 | 是否只证明了某个实现或预算下失败 |
| 计算、数据或实际需求驱动 | 约束及使用目标 → 设计选择 → 相应指标 → 代价 | 所报指标是否真正对应使用需求 |

这些主线可组合，不必换成固定标题。实际 track/type 归属由当届官方规则决定。

## 标题与摘要

### 标题

用准确的研究对象、改变或发现帮助检索和定位。缩写要值得记住，而不是为了凑词发明名字。题目中的 efficient、robust、general、optimal 等都应有明确定义和证据范围。不要为模仿经典标题而套用 “X Is All You Need”。

### 摘要

摘要是主张最集中的地方。检查四项信息是否足够：具体问题；核心思想或发现；最有辨识度的证据；必要的作用范围。顺序与篇幅取决于贡献，不能机械要求各占一句。

- 方法稿：说清方法为何针对现有困难；避免把所有模块名称压进摘要。
- 理论稿：保留问题类、关键条件、结果形式及其相对意义。可解释主结果而不塞满全部技术记号。
- 经验稿：说明研究了什么、如何比较、观察到什么；不要伪装成新算法。
- 负结果稿：点明反驳的是哪一个具体命题，而非笼统宣布整个方向失败。

数字要附带必要的任务、度量和比较口径。没有正式显著性分析时不加 statistically significant；不能凭几项实验改写成 consistently across all settings。缺少关键材料时，先交付有依据的部分并说明缺口，不将编造结果填入“最终摘要”。

摘要与引言中的每个强主张都应在正文有着落。摘要不靠引用外部文献才能理解。当前模板决定格式；例如 ICML 2026 的 4–6 句是建议，不是三大会通用规范。

## 引言：让贡献有必要性

用最短的背景把读者带到具体任务。接着解释最接近方案在哪种条件下受限、缺少哪种认识，以及为什么现有直观修补还不足。

核心思想应早于实现细节出现。可以通过一个失败例、简单构造、概念图或现象图说明；只有确实帮助理解时才放首页图，不强制“teaser figure”。

贡献列表若有，应写研究产出：新增能力、结果、发现或可验证资源。不要把“提出方法、做实验、组织如下”包装成三项独立科学贡献，也不要把一个思想拆成三个近义贡献。

比较应具体：“依赖某类标注”“需要某种信息”“只保证某个范围”，比“现有方法不够好”更有辨识度。首次、唯一、首次统一等主张需要相应文献核查；不能仅因作者未给出相关工作，就替作者声称此前无人研究。

每段结尾不必重复意义。让后一段回答前一段自然产生的问题，避免连续使用 Moreover、Furthermore、Importantly 充当逻辑连接。

## 相关工作：围绕比较轴组织

按与贡献相关的假设、目标、信息、计算、适配方式或评估设置分组，不按发表年份罗列摘要。

一个比较段应说明已有方法做到了什么、与当前工作最关键的关系，以及差异为何影响本问题。正面承认接近的思路；“组件来自前作”与“组合和认识具有价值”可以同时成立，SimCLR 提供了范例。

区分概念性前作与实际实验基线。引用理论工作不意味着实验证明优于它；列为基线也不等于已经比较了所有相关方法。核对实际引用版本和归属，不把预印本上传年当会议年。

不要通过删除自引用达到匿名。按目标会议规则第三人称引用既有工作，并处理可能泄露身份的措辞和链接。

## 方法：从设计理由到可执行定义

先让读者知道输入、输出、训练信息、测试信息和要优化的对象；再给总体流程，然后展开关键构造。

内部诊断每个主要设计是否需要补足以下信息；正文只补当前读者确实缺少的部分，不把四问展开为固定四段：

1. 它解决哪个已经说明的困难？
2. 操作、变量和目标如何定义？
3. 相对于已有做法改变了什么？
4. 这项选择由推导、实验还是启发支持？

区分理想目标、可计算代理目标、随机估计器及代码中实际优化的损失。若重加权、近似、截断或替换目标，解释原因，不把它们悄悄称为等价。AEVB、GAN 和 DDPM 是不同情形的范例。

区分训练和推断中的行为，以及元训练、适配与测试中的数据使用。算法框应补足可执行步骤；不要与公式和文字三次逐行重复同一内容。新符号在需要处定义，避免为单次出现的常见概念增加缩写。

理想化分析和实际算法的差异要明确，例如最优内层解与有限更新、完整梯度与估计量、连续分布空间与有限参数化网络。说明差异并不等于已证明实际版本继承所有性质。

## 理论：先说结果回答什么

定理之前说明它回答的问题，以及相对已有结果的变化：更弱条件、更清楚的依赖关系、更优界、下界或不可行性。定义关键量并交代结论的尺度。

定理陈述保留量词、概率方式、参数区间、增长条件和常数依赖。定理之后仅在提供新的结果含义、关键尺度、非显然边界或纠正相关误解时解释；定理和已有假设已足够清楚时不重复复述。证明思路只展开帮助理解贡献的障碍、直觉和关键步骤。

主文保留判断结果所必需的假设与结果；完整长证明可按会议规则放附录，但提供可追踪的引用。不能把限制全部藏入附录，再在摘要写无条件结论。

特别检查：

- 存在某类坏例子，不表示所有问题失败。
- 次线性遗憾、目标值收敛、参数收敛和全局最优不同。
- 总体／无限宽度／无限数据分析，不自动覆盖有限模型。
- 上界更小须在可比条件与参数范围下解释，不能仅比较大 O 形式。
- 有主张的理论价值即可成立；不要为“像会议论文”凭空增加实验。

## 实验、讨论与篇幅

实验写作详见 [evidence-and-experiments.md](evidence-and-experiments.md)。每组实验回答明确问题，信息由设置、图表和正文共同承接；结果段只写新增判断与关键证据，不要求每段重复范围。不要逐格复述整张表。

讨论要解释研究改变了什么认识、何种代价或失效条件仍存在，以及哪些问题仍未解决。局限要具体，例如可用监督、计算预算、分布和任务范围；少用没有信息的“未来将研究更多数据集”。

坦诚局限与否定全部成果不同。证据支持的结论可以明确陈述；未完成的延伸用未来或假设语气，不能在结论突然扩展到未测试领域。

压缩篇幅的优先次序：

1. 删除通用背景、重复贡献、教程式前置材料和结果逐格复述。
2. 合并承担同一论证任务的段落，简化多余符号和重复算法解释。
3. 将完整推导、扩展结果、全部超参等合适细节放附录，并在主文定位。
4. 保留核心困难、关键新意、决定性证据、主要实验协议、关键假设与边界。

压缩后重新检查指代与证据链接。不得通过缩小字体、调整负间距或把主要证据移走来解决正文超限。

无论是否超页，初稿完成后独立进行一次无损删改：删除不损失事实、必要推理、清楚指代、有效范围或衔接的句子，合并部分重复。条件已在设置或假设中明确时不重列；成熟、准确的句子可以保持原样。此步与随后[终稿清理](final-cleanup.md)分开执行。

## 句子、语气与术语

用动作和对象替代宣传词。例如用“降低固定协议下的平均误差”替代“显著推进领域”。但不把所有自信判断一律降为 may 或 potentially。

| 证据状况 | 合适的表达动作 | 易发生的越界 |
| --- | --- | --- |
| 条件下已有证明 | state / establish / prove，并保留条件 | 无条件 guarantee |
| 实验观察 | observe / find / improve on 指定设置 | prove / universally solve |
| 与某解释相容 | suggest / be consistent with | identify the sole cause |
| 尚未验证的设想 | conjecture / hypothesize | 已有机制结论 |
| 真实未完成计划 | plan / leave for future work | have demonstrated |

不要机械限制被动语态、第一人称、长句或特定词。若“novel”确有必要且有依据，可以保留；更常见的改进是把“新在哪里”写出来。名词、算法名和技术术语按[术语协议](terminology-protocol.md)核验后保持一致，不为避免重复而换同义词。仅在真实比较、反例或纠正相关预期时使用对立表达，直接判断不加虚设转折。

## 审稿回复

先辨明质疑：正确性、证据、贡献、表达，或范围之外的扩展。围绕最影响判断的问题作答。

有用的回复通常包含：直接答案；已有证据或实际新增分析；论文中已完成的修改及定位；仍存在的限制。没有必要每次套成四段。

准确区分“已有”“本次完成”“打算进行”。不编造新结果、不声称上传了没有上传的修订版。受当届规则限制不能修改 PDF 时，清楚表述回复中的解释以及可在未来版本修订的内容。ICML 2026 与 ICLR 2027 在此处规则不同。

审稿人误解可能提示原文不清楚；用可核对的解释回应。对不可比或要求扩大研究范围的建议，说明当前问题与证据边界，不用讽刺或地位诉求。除非用户明确授权，不代为发布回复。

## 投稿前核查

普通润色不需要完整走此流程。用户要求合规或准备提交时，核查目标届次／轨道／阶段的官方作者页与模板：页数口径、摘要格式、匿名及自引用、附录与补充材料、必需声明、checklist、回复或终稿变化。

将结论分为已核实、需要作者事实、来源尚未核实。只有读取原稿和相关材料、并核查适用要求后，才判断某项已满足；不能把“模板中有这个栏目”当作研究事实正确。
