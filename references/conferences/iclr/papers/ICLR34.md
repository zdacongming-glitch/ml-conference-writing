# ICLR34 · Memory Networks

- 会议：ICLR 2015，主会。
- 全文来源：[1410.3916](https://arxiv.org/pdf/1410.3916)。
- 实际阅读：主文§1–6全文，图1–4、表1–3及图表注；PDF pp.1–10。附录各任务生成细节未逐项复核。
- 阅读日期：2026-10-19。
- 以下为独立撰写的结构分析，非论文原文摘抄。

## 摘要的信息选择

先定义可读写长时记忆与推断组件的组合，再限定QA实例和两类任务；通用框架与本稿已验证实现明确有层级（p.1）。

## 引言的推进

§1用读取事实后回答问题这一具体需求解释压缩状态限制，随后把记忆与已有学习器组合为接口；到§2才正式列I/G/O/R四组件（pp.1–2）。

## 方法、直觉与定义的顺序

§2给通用流程及尚未实现的管理选择，§3给具体MemNN：检索一个/两个事实、回答词、训练监督，然后逐项增加分句、hash、时间和未知词。每项扩展对应可辨认的失败情形（pp.2–6）。

## 图表的证据角色

图1具体故事解释两阶段检索，表1/2报告大规模QA与速度–质量取舍，表3按时间/对象/难度消融；图2–4展示回答含成功及无意义例子，未仅保留漂亮对话（pp.4,7–10）。

## 结尾的作用

§6明说只探索一种实例，把弱监督、更难QA和其它模态作为后续任务；与通用框架的广度保持实证承诺差别（p.10）。

## 可迁移规范及条件

框架稿先建立接口，再给足以运行的实例，把未实现扩展明确留作可能；reasoning主张需操作任务、深度和对照支持。反例：训练使用支持事实标签，RNN/LSTM难利用该额外监督，不能把全部差距归于内存结构或称弱监督端到端方法。

## 版本与反例

arXiv v11（2015-11-29），会议后作者修订。14M QA的F1是已标注候选重排评测，hash速度主要来自减少候选，不等于任意开放域问答整体80倍加速。
