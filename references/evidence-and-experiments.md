# 把实验写成支持主张的证据

这是**编辑建议**；官方依据包括 [ICML 2026 审稿标准](https://icml.cc/Conferences/2026/ReviewerInstructions)、[ICLR 2027 审稿指南](https://iclr.cc/Conferences/2027/ReviewerGuidelines)、[NeurIPS 2026 审稿指南](https://neurips.cc/Conferences/2026/ReviewerGuidelines) 及 [官方 checklist](https://media.neurips.cc/Conferences/NeurIPS2026/Formatting_Instructions_For_NeurIPS_2026.zip)。具体实验设计按研究问题决定，下文不是会议统一要求的实验套餐。

## 目录

- 主张与证据匹配
- 比较协议与数据边界
- 消融与机制解释
- 不确定性和数值措辞
- 计算、资源与不同研究类型
- 图表、正文与附录

## 主张与证据匹配

以下检查主要用于内部核对。正文由设置、图表和结果段共同提供必要信息；只有会影响当前结论的缺口才就地解释，其余待确认事项放在给作者的说明中。

编辑前可以内部建立下表；不必每次向作者输出大表格。

| 想说的结论 | 对应证据应回答什么 | 常见越界 |
| --- | --- | --- |
| 指定任务中更准确 | 哪种协议、哪些可比基线、什么指标与波动 | 个别最佳点变成全面领先 |
| 更高效 | 同等质量下成本，或同等成本下质量 | 只报参数少便称运行更快 |
| 某设计有作用 | 对照改变什么、其他因素是否可比 | 删模块同时缩模型却归因于机制 |
| 对某扰动稳健 | 扰动类别、强度、范围及失效点 | 某种噪声结果变成任意 OOD 保证 |
| 更好地泛化或适配 | 未见的对象是什么，训练信息是否越界 | 新样本、新类别、新任务、新分布混同 |
| 负结果 | 有多强的实现、调参与预算，排除哪些解释 | 一次失败变成理论不可能 |
| 理论保证 | 精确条件下证明的对象与算法版本 | 用有限基准结果“证明”普遍保证 |

如果证据不匹配，选择缩小措辞、补充必要解释，或明确提出待验证项。写作任务本身不授权虚构或偷偷执行大规模实验。纯理论结果无需为凑齐这张表添加经验研究。

## 实验开头：先给问题和协议

先列实际需要回答的研究问题，再说明数据、指标、比较对象与基本协议。问题可以自然融入段落，不强制编号 RQ1、RQ2。

主表往往回答“在可比设置下是否有效”；后续对照回答关键设计、敏感性、计算代价或适用边界。只保留与主张有关系的组合，不为了数量堆数据集。

检查设置、图表及正文共同提供的信息是否足以支持判断。结果段允许只写关键比较；范围已由设置明确时无需重复，不把“判断—观察—解释—范围”当默认模板。对会改变读者结论的例外才就地说明，避免逐格复述或每段附加通用限制。

## 比较协议与数据边界

首先确认最接近、最有解释力的基线；一个简单基线有时比很多过时复杂方法更能检验贡献。比较对象应服务于研究问题，不按名气选择。

检查可能改变结论的差异：骨干、预训练、数据量、额外标注、数据增强、模型容量、训练时长、调参空间、验证集、模型选择、测试时增强与集成。

不能总能控制所有条件；这时明确哪些保持一致、哪些不同，以及不同是否限制归因。公平比较不意味着强制所有算法相同超参，而是给予合理调优并报告影响比较的预算与选择方式。

区分复现结果与引用结果；引用他人表格时标明来源和不可直接比较之处。不要把缺失单元格视为落后，也不要把验证集成绩当独立测试成绩。

数据划分、过滤、标签、适配或模型选择中，测试信息是否被使用必须写清。重复在测试集挑提示、超参或模型，会改变“测试”结果的解释。对预训练污染、近重复或闭源数据不确定性，报告实际做过的检查；未检查不能写成不存在。

## 消融与机制解释

消融首先检验的是某个可操作改动下的表现差异。要判断它支持哪个解释，应说明同时变化的参数量、计算量、损失尺度、优化难度、训练长度及信息可用性。

例如删掉模块后效果下降，支持“完整系统在此比较中更好”；若参数量也下降，则不能单独识别该模块所声称机制的作用。可建议参数或计算匹配的替代、不同实现的对照、诊断量或干预，但只针对实际需要的主张。

受控干预可以支持特定实验范围内的因果比较；不要把所有消融都说成“毫无因果信息”。反过来，一次消融也不自动证明唯一机制。注意力图、t-SNE 图、梯度或表示的相关性图需要相应解释边界。

敏感性分析报告真正有影响的选择及已观察范围；别把固定一个随机种子的单点曲线称为普遍稳定性。

## 不确定性与数值措辞

说明随机性的来源和独立单位：初始化、数据划分、任务、训练运行、评估样本或人类评分者。一次训练的多个测试样本不能当成多个独立训练运行。

明确“均值 ± 数值”中的数值是 SD、SE、CI 或其他统计量，给运行数、计算方法和必要假设。不要从裸表推测这些定义，也不要编造随机种子数量或统计检验。

存在重复或层级依赖时，解释汇总和重采样单位；图节点、同一任务中的样本、同一提示的多个生成结果不必然独立。对比较实验，配对设计和跨任务汇总应按实际协议说明。

没有足够证据时，把“显著优于”改成准确的观察描述；缺失的不确定性信息告知作者，不必给每个结果添加同一限制。不要为语气克制而抹掉真实且已有依据的显著性。

### 数值必须保留分母

若准确率从 80% 到 82%，是 **2 个百分点**，相对准确率增加 **2.5%**，相对错误率减少 **10%**；三者不能互换。采用哪一种须与指标、原稿和作者意图一致。

若运行时间从 3 小时降至 2 小时，耗时减少约 **33.3%**，加速比为 **1.5 倍**。不要写成减少 50%。这些数值仅为解释口径的例子。

对平均改进说明先算每任务差值还是先汇总指标，是否加权，不能自行选能放大提升的口径。统计量未定义时先保留原始结果并询明，不自造平均数。

## 计算效率与复现叙述

区分参数量、FLOPs、显存、运行时间、延迟、吞吐量、GPU 小时和能耗。它们各回答不同问题，不能直接互相替代。

运行时间比较至少说明影响判断的硬件、精度、batch、软件或实现、测量范围及是否包含预处理／编译／数据传输。使用理论或峰值算力估算时明确标为估算。训练步数减少也可能被单步成本抵消。

说明比较是等预算、等精度，还是两个固定设置；不要用多个同时变化的因素把结果归因于一个算法选择。适用时区分训练、适配和推断成本，以及单次运行、调参和总研究投入。

可复现叙述指向实际代码、环境、版本、数据处理和配置。代码不可公开时，准确说明现有可验证途径及限制；不能承诺不存在的匿名仓库、模型权重或未来开放日期。

## 按研究类型追加必要信息

以下是条件性提醒，不要求每篇全部覆盖。

| 类型 | 对解释结果最有影响的信息 |
| --- | --- |
| 表征学习 | 预训练数据；冻结或微调；linear probe 训练细节；是否使用标签；评估前后的表示位置 |
| 元学习／少样本 | 任务及类别划分；support/query；适配信息、步数和数据；元训练成本；任务间汇总 |
| 图学习 | transductive 或 inductive；训练能见哪些节点、边、特征和标签；是否在未见图上测试 |
| 强化学习 | 环境及版本；交互预算；独立运行；评价协议；跨任务汇总；离线与在线信息边界 |
| 生成模型 | 条件信息、样本数、采样预算；质量、覆盖与似然对应的指标；选择展示样本的方法 |
| LLM／agent 评估 | 模型及访问日期或版本、提示和解码、工具权限、测试时预算；数据污染检查；评判器及人工验证；评估成本 |
| 理论驱动方法 | 理论假设与实际实现对应关系；实验证明了哪些现象、没有检验哪些保证 |
| 应用驱动研究 | 使用场景、真正影响决策的指标、数据取得与标注、适用人群或环境；必要时报告伦理与使用限制 |

现代系统变化快，涉及具体模型、榜单或评判方案的事实须查一手资料。经典论文卡片教的是论证方式，不能替代当前领域的评估协议。

## 图表、正文与附录

主图主表应直接支持一个核心判断。图注让读者知道对象、轴、指标方向、误差条、固定和变化的条件；决定性条件不能只存在于读者未必找到的附录。

表格标明引用或复现、可比配置和不确定性定义。加粗最佳点不等于统计显著；多指标时避免把只有某一项占优说成全面胜出。

定性样本说明选择方式，包含与主张相关的失败情况；不能把精挑示例写成随机样本。可视化帮助理解，不自动构成机制或因果证明。

正文保留核心研究问题、主要设置、关键结果和必要局限；附录承载完整配置、扩展表、额外诊断与长证明。压缩时仍要让主文足以被评价。
